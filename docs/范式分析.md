# 范式分析与模式选择理由

逐表判定（1NF → 2NF → 3NF → BCNF），并说明为应用方便而保留的反规范化设计。

## 一、范式判定

| 表 | 主键 / 候选键 | 判定 | 说明 |
|---|---|---|---|
| manufacturer | PK manufacturer_id；候选键 name、uscc | **BCNF** | 所有非主属性完全依赖候选键，无传递依赖 |
| vbp_batch | PK batch_id；候选键 batch_no | **BCNF** | 批次信息仅依赖批次 |
| announcement | PK announcement_id；候选键 notice_no | **BCNF** | 公告信息仅依赖公告 |
| selected_item | PK selected_id；候选键 (batch_id, seq_no) | **BCNF** | 单主键无部分依赖；两个决定因素均为超键 |
| supply_province | PK (selected_id, province) | **BCNF** | 复合主键，data_kind 依赖整键，无部分依赖 |
| violation | PK violation_id | **BCNF** | 违规信息仅依赖违规记录 |
| user_account | PK user_id；候选键 username | **BCNF** | 账号信息仅依赖账号 |
| drug | PK drug_id；候选键 approval_no | **3NF（含派生冗余）** | core_name 由 generic_name 派生，见反规范化① |
| catalog_entry | PK entry_id；候选键 (version,section,catalog_no,product_name,dosage_form) | **3NF（含派生冗余）** | norm_name 由 product_name 派生，见反规范化① |

## 二、反规范化设计与理由（应用方便性权衡）

### ① 派生归一化列：drug.core_name / catalog_entry.norm_name
- **问题**：core_name = 去盐基(generic_name)，norm_name = 去括号别名(product_name)，均传递依赖于主键，严格说不满足 3NF。
- **取舍**：保留为**派生冗余列**。跨源核验（目录↔批文、集采↔目录）依赖核心名匹配，若每次查询临时计算则无法走索引、且规则散落。由统一的归一化函数（`parse_catalog.core_of`）在入库时生成，保证与源字段一致。
- **规范替代**：可建"通用名-核心名"映射表（主数据管理）彻底消除派生列，本项目以映射函数 + 台账（drug_match.csv）实现同等效果。

### ② selected_item 保留清单原始字段
- **问题**：product_name / dosage_form / specification / pack_desc 与 drug 表的品种信息存在冗余。
- **取舍**：**有意保留原文快照**。核验的目标是"清单原文 vs 规范化品种 vs 目录"三者对照，若只存 drug_id 外键则丢失清单原始写法，无法核验"名称/规格不统一"这一真实问题。
- **规范替代**：品种信息归 drug，清单仅存 drug_id + 价格 + 包装；本项目保留原文列用于溯源核验。

### ③ violation 用文本而非外键关联
- **问题**：violation.manufacturer / product_name 为文本，未规范化为外键。
- **取舍**：**弱关联是本选题核心**。违规公告的企业名/药品名需与中选记录做文本匹配以发现"名称不一致""已取消资格但清单未更新"等矛盾；若强制外键则无法表达这类不一致。
- **规范替代**：核验确认后可回写 manufacturer_id；当前保留文本键 + 视图做匹配。

### ④ drug.approval_no 当前为模拟占位
- NMPA 官方不可批量获取，批文号为模拟；generic_name/core_name 为真实。属**数据可得性限制**而非范式问题，已在 README 标注 data_kind。

## 三、结论

- 主体结构（企业/药品/批次/公告/中选/供应/违规/目录）满足 **BCNF**。
- 三处反规范化（派生归一化列、清单原文快照、违规文本弱关联）均为**服务"交叉核验"这一核心应用目标**而保留，理由充分、有一致性生成规则与台账兜底。
- 关系模式兼顾了规范化程度与"跨源核验 + 来源追溯"的应用开发方便性。
