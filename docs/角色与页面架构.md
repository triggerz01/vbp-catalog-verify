# 角色与页面架构

> 本文档是角色化体验改造的设计契约：先定架构，再改代码。原则——网页服务于关系模型、SQL、约束、权限与业务流程，不做静态汇报页。

## 一、核心结构问题（修复对象）

- 原首页把五种角色卡片平铺，登录前后首页与导航几乎不变，角色只存在于账号字段与文案。
- 修复：公共首页与角色工作台分离；登录后进入按服务端角色渲染的 `/workspace`；导航随角色变化；权限由后端装饰器保证（按钮隐藏不等于权限）。

## 二、角色模型与权限矩阵

角色存于 `user_account.role`（服务端判定，不信任前端）。`user_account` 不绑定具体医院/药企，故**不伪造"我院/我司"**；药企工作台用"选择企业"查看任意企业。

| 角色 | 公共查询 | 核验中心/统计 | 角色工作台 | 数据管理(写) |
|---|---|---|---|---|
| 公众（未登录） | ✅ | ❌（跳登录） | ❌ | ❌ |
| hospital 医院采购 | ✅ | ✅ | 采购核对台 | ❌ |
| pharma 药企合规 | ✅ | ✅ | 合规核对台（选择企业） | ❌ |
| researcher 研究员 | ✅ | ✅ | 研究核验台 | ❌ |
| admin 管理员 | ✅ | ✅ | 数据管理台 | ✅（admin_required） |

- 公共查询 = 中选记录 / 医保目录 / 企业 / 违规名单 / 公告（来源追溯）。
- 写操作仅 admin，由后端 `admin_required` 拦截；普通角色访问 admin 路由返回 **403**；未登录访问 `/workspace` 跳登录；登录成功默认进 `/workspace`。

## 三、路由地图

| 层级 | 路由 | 可见性 | 对应数据库能力 |
|---|---|---|---|
| 公共首页 | `/` | 所有人 | 项目说明 + 核心查询 + 来源追溯 + 真实/模拟边界 |
| 登录 | `/login` `/logout` | 所有人 | user_account + pbkdf2 |
| 角色工作台 | `/workspace` | 登录 | 按角色渲染（见下） |
| 数据查询 | `/selected` `/selected/<id>` | 所有人 | 动态 WHERE + EXISTS + 多表 JOIN |
| 数据查询 | `/catalog` | 所有人 | 目录 LIKE + 甲乙类 |
| 数据查询 | `/manufacturers` `/<id>` | 所有人 | LEFT JOIN + GROUP BY |
| 数据查询 | `/violations` | 所有人 | violation + 公告 JOIN |
| 来源追溯 | `/announcements` | 所有人 | announcement + 关联计数 |
| 交叉核验 | `/verify` | 登录 | 3 视图 + 核心名匹配 + 价格聚合 |
| 统计分析 | `/stats` | 登录 | GROUP BY / HAVING / 聚合 |
| 数据管理 | `/admin/selected/new|edit|delete|invalidate` | admin | 事务 + CHECK/UNIQUE + 状态机 |

## 四、各角色工作台（首屏顺序：身份/任务 → 主操作 → 异常 → 指标）

### 医院采购 `/workspace`（hospital）
- 主操作：按药品/省份查中选价与供应企业（→/selected）。
- 异常：违规风险品种（v_violation_conflict）——已取消资格/断供但清单仍有效。
- 指标：中选/备供记录数、覆盖省份数、医保甲/乙类品种数。
- 口径提示：供应省份为模拟演示数据。

### 药企合规 `/workspace`（pharma）
- 主操作：**选择企业**（下拉选 manufacturer，非"我司"）→ 查看该企业中选与违规；同品种竞争价格对比。
- 异常：所选企业的违规记录、批文/目录一致性（v_catalog_no_approval）。
- 指标：所选企业中选记录数、平均中选价、违规数。
- 无企业绑定 → 默认提示选择企业。

### 研究员 `/workspace`（researcher）
- 主操作：四类交叉核验入口（违规/批文/目录/价格）+ 统计分析。
- 异常：各类核验的矛盾计数与明细链接。
- 指标：四源记录规模、真实/模拟占比、来源公告数。
- 附核验口径说明与名称匹配局限。

### 管理员 `/workspace`（admin）
- 主操作：新增中选记录、编辑/删除、标记失效（核验闭环）。
- 异常：待处置冲突（v_violation_conflict，含"标记失效"操作）、数据质量（待复核/未匹配/待补录）。
- 指标：记录规模、待处置冲突数、模拟数据占比。
- 管理区与公共查询分开：管理操作集中在工作台与详情页，公共查询不含管理术语。

### 公众
- 只用公共查询与来源追溯；不显示"处置/标记失效/数据管理"等内部术语。

## 五、设计规范

- 紧凑导航、提高内容密度；首屏顺序 = 身份/任务 → 主操作 → 异常 → 指标。
- **表格用于比较，卡片用于概览**（指标用卡片，明细用表格）。
- 语义色：**红=真实风险**（违规/矛盾）、**黄=待复核**（名称匹配待确认/模拟数据）、**绿=已解决/一致**。
- 正文字号 ≥16px，标签 ≥14px。
- 不增加没有数据库支持的功能；每个入口都落到真实表/视图/SQL。

## 六、测试要求

- 五种身份 `/workspace` 内容不同；公共首页无角色全集；普通角色无管理员操作；越权访问 admin 403；未登录 `/workspace` 跳登录；登录默认进 `/workspace`。
- 运行 `python src/test_backend.py` 全部通过。
